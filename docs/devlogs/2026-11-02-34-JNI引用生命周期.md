## 0. 一句话

LocalRef 的分配、解析、帧提升原本已经能跑；这次补的是**回收侧**：
删除即回收 cell、局部帧弹出时回收整段、线程解绑/退出回收全部本地引用，
并补上弱全局引用与 `EnsureLocalCapacity` 的真实语义。

---

## 1. 改动前的状态

`src/runtime/jni/refs/ref_table.{hpp,cpp}` 已有：

- 句柄 = guest 内存里 8 字节 cell，内容是对象地址；
- 本地引用按 `TPIDR_EL0` 分线程，全局引用实例级；
- `PushLocalFrame` / `PopLocalFrame`（带 survivor 提升）、`DeleteLocalRef`、
  `NewLocalRef`、`GetObjectRefType`。

缺口：

1. `DeleteLocalRef` 只把 cell 写 0，句柄留在 `handles` 向量里，cell 永不回收；
2. 线程退出 / `DetachCurrentThread` 不清理本地引用和 `JNIEnv` 槽；
3. `EnsureLocalCapacity` 恒返回 `JNI_OK`，没有容量概念；
4. 弱全局引用没有 dispatch，`GetObjectRefType` 永不返回 `WeakGlobal`；
5. `callRegisteredNative` 用 key `0` 压帧，而 native 内部 JNI 调用按真实
   `TPIDR_EL0` 记录引用 —— **弹帧释放不到这些引用**。

## 2. 设计

参考 ART `LocalReferenceTable` 的槽位语义（`Remove` 的 top 剪枝 + free list，
`PushFrame/PopFrame` 只移动 top 索引，`kMaxTableSize = 128 MiB`,
`local_reference_table.h:395`），落到当前的 guest cell 模型上。

### 2.1 线程状态

```text
ThreadState
  handles          slot -> cell；0 是洞
  frames           push 时的 handles.size() 标记
  reusable_slots   当前帧内可立即复用的洞（>= top mark）
  pending_slots    当前帧以下的洞，只能等外层帧弹出后复用
  slot_of          cell -> slot，删除时校验归属
  live             活引用计数
```

- `DeleteLocalRef`：校验 `handle` 属于当前线程且是活引用；写 0、cell 进实例
  级 free list、从 `slot_of` 摘除。若删除的是栈顶槽位则直接 `pop_back` 并
  向上剪枝（LIFO 场景不增长）；否则是 `>= top mark` 时进 `reusable_slots`，
  在帧以下则进 `pending_slots`。
- `newLocal`：优先复用 `reusable_slots`，其次 `push_back`；cell 优先复用 free
  list。因此“调用内创建、调用内删除”的模式不增加 cell，也不增加槽位。
- `PopLocalFrame`：先把 survivor 解析成对象地址，再回收 `[mark, size)` 的
  cell、截断向量；`pending_slots` 中落入外层帧的洞转移到 `reusable_slots`。
  survivor 为空或已删除时返回 0（旧实现会返回一个指向空 cell 的句柄）。
- 每线程上限沿用 ART 的 128 MiB / 8 = `kMaxLocalRefs`；`EnsureLocalCapacity`
  按 ART 的保守口径（`max - top_index`，不扣除洞）判断，失败返回 `JNI_ERR`。
  `PushLocalFrame(capacity)` 先做同样的检查，再压帧。

### 2.2 帧必须用执行线程的 key

`callRegisteredNative` 之前固定用 key `0`。guest native 实际运行在调度器主
线程上，JNI 调用按运行中的 `TPIDR_EL0` 记账，于是帧和引用不在同一个表里，
弹帧是空操作。现在先取 `ThreadScheduler::mainThreadPointer()`（主线程当前
`tls_tp`），帧、`jclass`、对象实参和 `JNIEnv` 槽都用这个 key。

### 2.3 Detach 与线程退出

- `DetachCurrentThread` 调用 `JniState::releaseThread(TPIDR_EL0)`：释放该
  key 的全部本地引用、清零并回收 `JNIEnv` 槽。
- 调度器在 `finalizeThread` 里通过 `SchedulerConfig::thread_exit` 回调通知
  JNI 层。libc 的 `__set_tls` 会改写 `TPIDR_EL0`，所以 `RuntimeThread`
  记录线程运行过的每个 key（`tls_keys`），退出时逐个释放。
- 主线程的 `JNI_OnLoad` 不额外压帧：ART 在 `LoadNativeLibrary` 里也不建
  局部帧，本地引用活到线程结束；现在由线程退出回收，行为对齐。

### 2.4 弱全局引用

`NewWeakGlobalRef` / `DeleteWeakGlobalRef` 进 dispatch，单独的
`weak_globals_` 集合，`GetObjectRefType` 返回 `JNIWeakGlobalRefType`。
**没有 GC，所以弱引用永远不会被清除**；它与强全局的区别只在类型和删除
API。当前目标没有依赖弱引用清除的场景。

## 3. 与 ART 的差异（有意保留）

| 行为 | ART | 本实现 |
| --- | --- | --- |
| 删除外层帧的本地引用 | 视为跨段，警告后 no-op | 允许删除（JNI 规范语义），洞延迟到帧弹出后复用 |
| 容量耗尽 | `ThrowOutOfMemoryError` + `JNI_ERR` | 返回 `JNI_ERR` 并告警；严格 Java world 未声明 `OutOfMemoryError` |
| 弱引用清除 | GC 时清空 | 无 GC，永不清除 |
| `JNI_OnLoad` 本地引用 | 活到线程 detach | 活到线程退出（主线程即实例停止） |

## 4. 测试

新增 `tests/unit/runtime/ref_table_test.cpp`（单元，无引擎）：

- 归属校验：别的线程删不掉；重复删除返回 false；`DeleteLocalRef(0)` 合法；
- cell 复用：删除后下一次 `newLocal` 拿回同一地址；
- 帧：嵌套帧、survivor 提升、已删除 survivor 返回 0、弹出后计数归零、
  帧以下的洞延迟复用；
- 容量：负值由调用方拒绝，`kMaxLocalRefs` 边界，删除栈顶后容量恢复；
- 全局/弱全局：类型、互相不通用删除、cell 跨类型复用后类型正确；
- 线程退出：释放全部本地引用与帧，其他线程不受影响，重新 attach 可复用。

结果：本构建 `ctest` 52/52 通过（含四个真实目标）。生产构建命令：

```sh
cmake -S code -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
ctest --test-dir build --output-on-failure
```

## 5. 已知限制

- 无 GC：弱引用不清除，`IsSameObject(weak, null)` 永远为 false；
- `EnsureLocalCapacity` 失败不抛 `OutOfMemoryError`（类未在严格 world 中声明），
  只告警并返回 `JNI_ERR`；
- 每个线程最多保留 `kMaxLocalRefs` 个槽位；超出后 `newLocal` 返回
  `OutOfMemory`，JNI 调用返回 0（与既有分配失败路径一致）。
