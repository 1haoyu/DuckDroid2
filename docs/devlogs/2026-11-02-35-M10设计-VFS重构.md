## 0. 一句话

把现在揉在 `VirtualFileSystem` 里的四件事拆开——**命名空间（挂载/路径）**、
**身份（Vnode）**、**打开描述（OpenFile/fd）**、**后端（谁真正读写）**——
用契约测试锁住现有行为，再补目录 fd + `getdents64`、`pwrite64`，
并把覆盖层的删除/重命名语义按只读根 + 可写沙箱说清楚。

---

## 1. 动机

### 1.1 现状

- `VirtualFileSystem` 约 1000 行，同时承担：路径归一化、挂载叠加、`/proc`
  合成、合成挂载、fd 表、stat 属主/时间戳、readlink、statfs。
- `File` 子类同时是“节点”和“打开描述”：`HostFile` 持有宿主 fd、路径、
  offset、size；两个 `open` 会各建一个对象，`dup` 靠 `shared_ptr` 共享。
- 目录在类型系统里不存在：`openPath` 对目录直接返回 `IsDirectory`，
  相对路径带 dirfd 直接 EBADF（`code/src/runtime/vfs/virtual_file_system.cpp:158`）。
- 写 syscall 面只到 `write`：`pwrite64`、`writev/pwritev`、`fallocate`
  都没注册；`pwrite64` 会落到 dispatcher 的 ENOSYS。

### 1.2 这次要一起修掉的具体问题

| # | 问题 | 位置 / 现象 |
|---|---|---|
| 1 | 叠加顺序隐式散落 | `resolveHost` 先查 `write_root` 再查 `host_roots`；`openPath` 又单独决定 `/proc`、合成挂载、宿主的优先级。改一处要同时看三处。 |
| 2 | 两个 open 没有共享身份 | `st_ino` 透传宿主；合成文件用 `hash(path)`；`getdents` 的 `d_ino` 无处可取。 |
| 3 | 目录不可表达 | 无 `DirFile`、无 `getdents64`、无目录 fd；`/proc/self/fd/N` 的 readlink 也只到普通文件。 |
| 4 | `pwrite64` 缺失 | `HostFile` 内部已有 `pwrite` 逻辑（`code/src/runtime/vfs/file.cpp:350`），但没有 `writeAt` 与 syscall 入口。 |
| 5 | 可写 open 丢 errno | `open` 把宿主失败统一折叠成 `PermissionDenied`（`virtual_file_system.cpp:490`），`ENOENT/EISDIR/EACCES` 不可区分。 |
| 6 | 覆盖层删除语义不对 | `unlinkat` 只对沙箱路径 `::unlink`；路径只存在于只读根时返回 `ENOENT`，而 devlog 22 写的是 `EROFS`。删除沙箱里遮蔽只读根的文件后，只读根的同名文件会重新出现。 |
| 7 | 覆盖层重命名语义不对 | `renameat` 只 rename 沙箱路径；源在只读根时返回 `ENOENT`（应为 `EROFS`）；跨挂载没有 `EXDEV`。 |
| 8 | `fcntl F_GETFL` 反推访问模式 | 访问模式由 `writable()` 猜测，`O_APPEND` 不可见。 |

### 1.3 unidbg 对照（只取结论）

unidbg 的模型是：**单个可写 rootDir + 每次 open 一个多态 `FileIO` + `IOResolver` 钩子链**。
没有挂载表、没有 vnode、没有只读层。它的 `DirectoryFileIO` 在 open 时把
宿主目录快照成列表，`getdents64` 每写一条就 `remove`，dirfd 相对路径直接
`throw BackendException`。

| 可借 | 不借 |
|---|---|
| `FileResult.success/failed/fallback` 的三态（决定 vs 继续找） | 单个可写根，无只读/沙箱语义 |
| open 时快照 + 游标的目录实现 | 破坏式消费列表（不能 rewind） |
| 后端按路径解析的 fallback 链 | `FileIO` 把 socket/vnode/offset 全塞进一个接口 |
| `ByteArrayFileIO` 式不可变生成文件 | `dup` 各建对象导致偏移不共享 |
| | 不检查 `O_RDONLY`、不处理 `O_TRUNC`、错误抛 Java 异常 |

结论：形状可以借，语义不能借。本设计保留 DuckDroid2 现有的“只读根 + 可写沙箱”，
把 unidbg 的目录快照思路修正后落到 Vnode/OpenFile 分层上。

## 2. 目标与非目标

### 2.1 目标

- **G1 分层**：syscall 层不出现宿主路径；后端不出现 fd/errno；叠加顺序只在
  `MountTable`/`OverlayFs` 定义。
- **G2 身份与描述分离**：`Vnode` 管身份和元数据，`OpenFile` 管 flags/offset；
  `dup` 共享 `OpenFile`，两次 `open` 共享 `Vnode`。
- **G3 目录面**：`open(O_DIRECTORY)`、`getdents64`、目录 fd 相对路径
  （`openat/fstatat/faccessat/unlinkat/renameat/mkdirat/readlinkat`）。
- **G4 写面补齐**：`pwrite64`；写错误保真（ENOENT/EISDIR/EROFS/EXDEV）。
- **G5 行为保持**：现有 gate 与四个真实目标的输出逐字节不变。

### 2.2 非目标

- `readv/writev/preadv/pwritev`、`sendfile/copy_file_range/splice`、`fallocate`。
  等真实目标踩到再补；`pwrite64` 单独做是因为它和 `pread64` 对称且成本极低。
- `chmod/chown/utimensat/symlinkat/linkat/mknod/statx`。
- 动态挂载/卸载、每进程 mount namespace、`pivot_root`。
- 持久化 whiteout（实例内内存即可；实例回收 = 换进程，M7 语义不变）。
- 通用 `ioctl`、文件锁、`inotify`。
- 目录项缓存淘汰策略：快照只活在打开的目录描述里，关闭即释放。

## 3. 架构

### 3.1 分层

```
                     guest SVC（arm64 ABI）
┌──────────────────────────────────────────────────────────────┐
│ L1 syscall 层   fs_handlers                                   │
│   read/write/pread/pwrite/openat/getdents64/stat/...          │
│   只做：读 guest 参数、调 Vfs、Error→errno、notifyActivity     │
└───────────────────────────┬──────────────────────────────────┘
                            │ Vfs 门面（guest 路径 + fd）
┌───────────────────────────▼──────────────────────────────────┐
│ L2 Vfs Core                                                   │
│                                                               │
│   MountTable  guest path ──最长前缀──▶ (Mount, relpath)        │
│   VnodeTable  (Mount, backend_id) ──▶ Vnode   身份/元数据      │
│   FdTable     fd ──▶ shared_ptr<OpenFile>     dup/close        │
│                                                               │
│   Vnode    : getattr/lookup/readdir/readlink/create/unlink/…   │
│   OpenFile : flags + offset + read/write/readAt/writeAt/seek   │
└───────────────────────────┬──────────────────────────────────┘
                            │ NodeOps / FileOps（唯一后端接口）
┌───────────────────────────▼──────────────────────────────────┐
│ L3 后端实现（彼此不知道，不知道 fd，不碰 errno）                │
│                                                               │
│   OverlayFs(upper=SandboxFs, lower=[HostRoFs...])              │
│   ProcFs     DevFs     PropertyFs     EventFs(eventfd/timerfd/…)│
│   SandboxFs  HostRoFs                                           │
└───────────────────────────┬──────────────────────────────────┘
                            │
                     宿主 OS / RuntimeMemory
```

横切（不占层）：`VfsConfig`（roots / write_root / uid/gid / clock / device）、
trace observer、`ActivityWaiters`。这些只被 Core 和后端读，不渗到 syscall 层。

### 3.2 模块布局

```
code/src/runtime/vfs/
├── vfs.{hpp,cpp}              # 门面：open/stat/getdents/...，持有下面三张表
├── mount_table.{hpp,cpp}      # guest 路径 → (Mount, relpath)，最长前缀
├── mount.hpp                  # Mount { prefix, backend, flags, fsid, statfs }
├── vnode.{hpp,cpp}            # Vnode 句柄 + 身份分配 + 元数据盖章
├── open_file.{hpp,cpp}        # OpenFile：flags/offset/append/closeable
├── fd_table.{hpp,cpp}         # fd → shared_ptr<OpenFile>
├── dir_cursor.{hpp,cpp}       # 快照条目 + 索引游标
├── backend.hpp                # NodeOps / FileOps / EnumerateOps 接口
└── backends/
    ├── host_ro_fs.{hpp,cpp}   # 只读宿主根（pread）
    ├── sandbox_fs.{hpp,cpp}   # 可写沙箱（O_* 透传、truncate/fsync）
    ├── overlay_fs.{hpp,cpp}   # upper/lower 合并、白障、readdir 去重
    ├── proc_fs.{hpp,cpp}      # 快照优先 + 生成器；显式 entry table
    ├── dev_fs.{hpp,cpp}       # /dev 字符节点
    ├── property_fs.{hpp,cpp}  # /dev/__properties__ 静态镜像
    └── event_fs.{hpp,cpp}     # eventfd/timerfd/pipe/epoll 的 OpenFile 后端
```

`StdioFile`、`MemoryFile`、`StaticFile`、`HostFile`、`EventFile` 等现有类
按角色拆分：内容/设备行为 → `FileOps` 后端；打开状态 → `OpenFile`。
不保留“既继承 File 又自己管 offset”的形态。

### 3.3 核心类型

```text
Mount       { prefix, backend, readonly, fsid[2], statfs profile, mount_id }
Vnode       { Mount*, backend handle, kind, dev, ino, mode/uid/gid/size/times }
OpenFile    { shared_ptr<Vnode>, flags, offset, append, closeable, FileOps* }
DirCursor   { vector<DirEntry>, index }   // DirEntry { name, type, ino }
```

`Vnode` 只是句柄 + 身份，不缓存文件内容。`MemoryFile` 的“打开时物化”
语义保持不变：物化结果挂在 `OpenFile`/后端句柄上，而不是全局。

### 3.4 不变量

1. syscall 层只看到 guest 路径和 fd；看不到宿主路径、`Mount*`、backend 类型。
2. 后端只返回 `Result<T>`/`Error`，不接触 errno，不知道 fd 编号。
3. 叠加优先级只在 `OverlayFs` 定义，其他层不重复判断。
4. 同一个 Vnode 上的所有 `OpenFile` 看到同一个 `dev/ino`；`getdents64`
   给出的 `d_ino` 必须等于随后 `fstatat` 的 `st_ino`。
5. `dup` 共享 `OpenFile`（含 offset）；两次独立 `open` 共享 `Vnode`，
   offset 各自独立。
6. 只读挂载上的变更操作返回 `EROFS`；跨挂载 `rename` 返回 `EXDEV`。
7. `getdents64` 不消费未写出的条目；`lseek(fd, 0, SEEK_SET)` 能复位。
8. 执行模型不变：所有 VFS 操作在单 guest CPU 的执行锁下发生；新增的锁仍然
   只有 `ActivityWaiters` 那一把。

## 4. 关键设计决定

### D1 挂载表与叠加

- 实例创建时固定一组 mount：
  - `/` → `OverlayFs(upper=SandboxFs(write_root), lower=[HostRoFs(host_roots)...])`
  - `/proc` → `ProcFs(snapshot_roots, synthesizer)`
  - `/dev` → `DevFs`
  - `/dev/__properties__` → `PropertyFs`
- 匹配规则：guest 路径的最长前缀；同前缀按注册顺序，后注册者优先。
- `/proc` 的“宿主快照优先、缺失再合成”收进 `ProcFs` 内部，不再由
  `openPath` 逐路径判断；`hostLookupPath` 的 `/proc/<pid>/x → self/x` 规则
  原样保留。
- `write_root` 为空时 `OverlayFs` 没有 upper：所有变更返回 `EROFS`。

### D2 身份（`dev/ino`）

- 宿主文件/目录：直接使用宿主的 `st_dev/st_ino`。`rename` 不改变身份。
- 合成文件/目录（`/proc`、`/dev`、属性区）：`ino = hash64(mount_id, guest_path)`，
  `dev = mount_id`。合成文件不可 rename，路径变化不影响语义。
- 不建全局 inode 表，也不做 inode 缓存淘汰。Vnode 是轻量句柄，需要时重建；
  `dev/ino` 由上述规则决定，重建后仍然一致。
- `getdents64` 的 `.` 用目录自身 `ino`，`..` 用父目录 `ino`（根目录的 `..` = 自身）。

### D3 覆盖层删除与重命名

- `unlink`：
  - 路径只在只读根 → `EROFS`；
  - 路径在 upper → 删除 upper；若 lower 同名存在，记录一条**内存白障**
    （`set<guest_path>`），之后 lookup/readdir 不再回落到 lower；
  - 路径在 upper 与 lower 都不存在 → `ENOENT`。
- `mkdir`：upper 里建；lower 同名存在 → `EEXIST`。
- `rename`：
  - 源只在 lower → `EROFS`；
  - 源在 upper：在沙箱内 rename；目标 lower 同名时不需要 copy-up，
    upper 直接遮蔽；跨挂载 → `EXDEV`；
  - 目标存在且是目录、源不是目录 → `EISDIR/ENOTDIR` 按内核。
- 白障在实例生命周期内有效，不做持久化；实例回收 = 换进程（M7 语义）。
- `open` 写意图：
  - lower 命中且没有 upper 副本，带 `O_CREAT` → 在 upper 创建，遮蔽 lower；
  - 带 `O_EXCL|O_CREAT` 且 lower 存在 → `EEXIST`；
  - 不带 `O_CREAT`、只命中 lower → `EROFS`；
  - `O_TRUNC` 只作用于 upper 已有文件；只命中 lower → `EROFS`。

### D4 目录枚举

- `open` 目录（带或不带 `O_DIRECTORY`）→ `DirFile`（`OpenFile` + `DirCursor`）。
  非目录带 `O_DIRECTORY` → `ENOTDIR`。
- **首次 `getdents64` 时快照**：`OverlayFs` 合并 upper + lower，按名字去重
  （upper 胜、白障过滤），加上 `.`/`..`；合成挂载由后端给出显式条目表。
  快照按名字排序，仅为回放可复现，不作为语义承诺。
- 游标是索引，不是破坏式列表：
  - `d_off = index + 1`；
  - buffer 不足时只写能放下的完整条目，不移动未写出的条目；
  - 第一条都放不下 → `EINVAL`（内核语义）；
  - 枚举完返回 0；
  - `lseek(fd, 0, SEEK_SET)` 复位；`SEEK_SET` 接受 `0..entries.size()`；
    其他 seek → `EINVAL`。
- `dup` 出来的目录 fd 共享 `OpenFile`/游标。
- `d_type`：REG/DIR/LNK/CHR/FIFO/SOCK；未知填 `DT_UNKNOWN`。
  宿主目录用 `symlink_status` 判断，避免把链接当普通文件。

### D5 dirfd 相对路径

- 目录 `OpenFile` 携带 `Vnode`；`resolve(dirfd, path)`：
  - `AT_FDCWD` → 当前工作目录（目前固定 `/`，语义不变）；
  - 其他 dirfd 必须是目录类型的 `OpenFile`，否则 `EBADF`/`ENOTDIR`；
  - 拼接后仍走 `MountTable` 归一化，`..` 不得越过根。
- 覆盖 `openat/fstatat/faccessat/unlinkat/renameat/mkdirat/readlinkat`。
- `/proc/self/fd/N` 的 readlink 对目录 fd 返回目录的 guest 路径。
- `AT_EMPTY_PATH` 仍由 `fstat` 承接，不新增路径解析分支。

### D6 错误模型

- 后端错误码集合按 ABI 语义分层：
  - `EROFS`（只读挂载上的变更、无沙箱写入）；
  - `EXDEV`（跨挂载 rename）；
  - `ENOTDIR/EISDIR/ENOTEMPTY/EEXIST/ENOENT/EACCES/EINVAL/ENAMETOOLONG`。
- `fs_handlers::toErrno` 只做 Error→负 errno 的单一映射；
  不再有“可写 open 一律 EACCES”的折叠。
- 宿主的 `errno` 在后端入口翻译一次，保留原语义。

### D7 stdio 与特殊 fd

- 0/1/2 在实例初始化时预装进 `FdTable`（`OpenFile` + `StdioFileOps`），
  flag 带 `closeable=false`。
- syscall 层删掉 `fd <= 2` 分支；`close(0/1/2)` 仍然返回 0 且不关闭宿主 fd。
- `dup(1)` 继续得到可见的 `/dev/stdout` 描述；`F_GETFL` 返回真实访问模式。

### D8 活动唤醒与 trace

- `OpenFile::write` 成功后统一 `notifyActivity()`；不再由 handler 逐类判断。
- `DUCKEMU_IO_TRACE` 的行格式保持不变（openat/read/pread/write/close/lseek），
  trace 调用收口到门面，避免重构改变分析面输出。

## 5. 分阶段与 gate

每个阶段单独提交，提交后 `main` 全绿；M10 整体作为一个可 review 的 PR。
S0–S2 不带新能力，只换结构；S3–S4 才加目录面。

### S0 契约基线（无生产代码改动）

**交付**：`code/tests/integration/10a_vfs_contract.cpp`

用现有 guest syscall 面把当前行为写成表驱动断言：

- 只读根读、沙箱覆盖读、无沙箱 EROFS；
- symlink 逃逸被拒；`/proc` 快照优先于合成；
- `/dev` 节点读写模式、`/dev/__properties__` root-owned；
- `dup` 共享 offset、stdio dup 可达宿主；
- `stat` uid/gid/时间戳注入；`statfs` 挂载分类；
- eventfd/pipe 基本读写与 `poll`。

**Gate**：`10a_vfs_contract` 通过；全量 `ctest` 不变。

### S1 命名空间层

**交付**：`mount_table.*`、`mount.hpp`、`backends/overlay_fs.*`；
`VirtualFileSystem` 的 `resolveHost/openPath` 改为走挂载表；行为不变。

**Gate**：`10a_vfs_contract` 全绿 + `10b_vfs_mounts`：
最长前缀、挂载只读位、合成挂载遮蔽宿主同名路径、
`/proc/<pid>/x → /proc/self/x`、`write_root` 为空时变更 EROFS。

### S2 Vnode / OpenFile 分离

**交付**：`vnode.*`、`open_file.*`、`fd_table` 改存 `OpenFile`；
`HostFile` 拆成 `HostRoFs`/`SandboxFs` 的 `FileOps`；
stdio 预装、删除 handler 的 `fd<=2` 分支；`pwrite64` 接入。

**Gate**：`10c_vfs_open_description`：
两次 open 的 offset 独立、`dup` 共享 offset、`pread/pwrite` 偏移正确、
`O_APPEND` 行为、`F_GETFL` 访问模式、stdio/close 语义、
写错误保真（ENOENT/EISDIR/EROFS 可区分）。

### S3 枚举与目录 fd 的系统调用面

**交付**：`dir_cursor.*`、`Vnode::readdir`、各后端 `EnumerateOps`；
`getdents64` handler；`DirFile`；覆盖层合并/白障；`ProcFs/DevFs/PropertyFs`
显式条目表。

**Gate**：`10d_vfs_dirent`：
`/data`（沙箱）、`/system`（只读根）、`/proc/self`、`/dev`、
`/dev/__properties__` 的枚举；部分 buffer、刚好放下、首条放不下 EINVAL、
EOF 返回 0；`lseek(0, SEEK_SET)` 复位；dup 目录 fd 共享游标；
`d_ino == fstatat st_ino`；`d_type`；覆盖层遮蔽去重；
删除 upper 后白障阻止 lower 复现。

### S4 dirfd 相对路径

**交付**：`resolve(dirfd, path)`；`openat/fstatat/faccessat/unlinkat/
renameat/mkdirat/readlinkat` 的 dirfd 分支；`/proc/self/fd/N` 目录目标；
`EXDEV`。

**Gate**：`10e_vfs_dirfd`：
目录 fd 下的 open/stat/unlink/rename/mkdir/faccess/readlink；
非目录 fd → ENOTDIR、坏 fd → EBADF；`..` 越界被拒；
跨挂载 rename → EXDEV；rename 后身份不变。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 热路径多一层虚调用，读/写变慢 | S2 后加一个 syscall 微基准（10 万次 read/write），与重构前对比；超过 5% 就内联 `HostRoFs/SandboxFs` 的 `readAt/writeAt` 快路径。 |
| `/proc` 快照优先级改坏 | `ProcFs` 内部保留原 `hostLookupPath` 规则；`10a`/`10b` 双份断言。 |
| `st_ino` 规则变化导致工具行为变 | 宿主文件沿用宿主 inode；只对合成文件引入 hash。`10d` 断言 `d_ino == st_ino`。 |
| 目录快照内存 | 快照只活在打开的目录描述里；关闭即释放；不对大目录设上限，但 devlog 记录。 |
| 白障只在内存 | 明确写进 `docs/runtime-contract.md`；实例回收即消失。 |
| 现有目标回归 | S5 逐字节对拍；任何输出差异视为 gate 失败，不进入下一阶段。 |
| M9 调试面并行 | M10 不改 `runtime/debug/` 与 RSP 路径；两者无依赖，可并行。 |
| 大 diff 难 review | 按 S0–S5 拆提交；S0/S1 纯结构，S3/S4 才是能力变化。 |

## 9. 实施偏差（2026-11-02 回写）

- **`File` 继续扮演 `OpenFile`**：`File` 本来就是进程内唯一的"打开描述"
  vtable（含 offset/flags/closeable），重命名会同时改动 eventfd/timerfd/pipe/
  epoll 与 JNI 消费面而不改变行为。实际落地的分层是
  `mount_table + backends + File(=OpenFile) + vnode identity`；
  `open_file.hpp` 管 flags/F_GETFL 语义，`vnode.hpp` 管 `dev/ino` 规则。
  `Vnode` 不做全局对象表，身份在 VFS 边界按 `(mount_id, guest_path)` 派生。
- **子挂载点由 VFS 注入父目录列表**：`DevFileSystem` 不知道自己下面还有
  `/dev/__properties__`；父目录 readdir 由 Core 按 mount table 补条目，并按
  子路径重新解析 mount 计算 `d_ino`。这样 `d_ino == fstatat st_ino`
  对跨挂载点也成立。
- **D3 的删除/重命名语义在 S1 就落地**：优先级已经收进 `OverlayFs`，
  没必要等 S3 再加白障；`10a` 契约不覆盖这些行为，因此没有违反"不改期望值"。
- **新增 `renameat2(276)`（flags=0）**：ROM 的 bionic `rename(3)` 走
  renameat2，原实现返回 ENOSYS。属于真实目标会踩到的缺口，随 M10 一并补。
- **保留 `O_CREAT` 自动创建父目录**：这是 M10 前的既有行为，真实目标
  （szstone 等）可能依赖；错误保真 gate 用不带 `O_CREAT` 的 open 验证 ENOENT。
- **目录快照在 open 时生成**，不是首次 getdents；两者语义等价（快照只活在
  打开的目录描述里），open 时生成让 `fstat` 的 size/时间与枚举同时可见。
- **`/proc` 枚举是"快照目录 ∪ 显式合成表"**：进程无关条目（version/cpuinfo）、
  进程目录（self/pid/thread-self）、进程条目（maps/mem/...）由 `ProcFs`
  显式列出；快照里额外的名字原样合并。
