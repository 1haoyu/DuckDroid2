## 0. 一句话

VFS 从"一个 1000 行的类"变成 **MountTable + 后端 + 打开描述 + 身份** 四层；
目录、`getdents64`、`pwrite64`、dirfd 相对路径和覆盖层白障全部落地，行为
由 `10a`–`10e` 五个 gate 锁住。生产构建 57/57，四个真实目标输出不变。

## 1. 落地结构

```
runtime/vfs/
├── vfs.{hpp,cpp}            # 门面：路径→mount→backend；fd 表；活动唤醒
├── mount.hpp                # Mount { prefix, backend, readonly, id, synthetic_identity }
├── mount_table.{hpp,cpp}    # 最长前缀匹配
├── backend.hpp/.cpp         # MountBackend：stat/open/access/mkdir/unlink/rename/readdir
├── vnode.hpp                # VnodeIdentity + hash64/hashPath/syntheticIdentity
├── open_file.hpp            # F_GETFL 可见的 flags（access | O_APPEND）
├── dir_entry.hpp            # DirEntry + DT_* + dirTypeFromMode
├── dir_cursor.{hpp,cpp}     # 快照 + 索引游标；linux_dirent64 打包
├── dir_file.{hpp,cpp}       # 目录打开描述（read/write = EISDIR）
└── backends/
    ├── host_ro_fs.*         # 只读宿主根（canonical + escape check）
    ├── sandbox_fs.*         # 可写 upper（O_* 透传、mkdir/unlink/rename）
    ├── overlay_fs.*         # upper/lower 合并、白障、readdir 去重
    ├── proc_fs.*            # 快照优先 + 合成回落 + 显式目录条目
    └── synthetic_mount_fs.* # /dev、/dev/__properties__
```

实例固定挂载由 `VirtualFileSystem` 构造：

- `/` → `OverlayFs(SandboxFs?, [HostRoFs…])`
- `/proc` → `ProcFs(OverlayFs 快照视图, 合成器)`
- `/dev`、`/dev/__properties__` → `SyntheticMountFs`

`MountBackend` 只见挂载内相对路径，只返回 `Result`/`Error`；宿主 errno 在
后端入口翻译一次。目录 fd 和路径拼接都在门面，后端不知道 fd。

## 2. 新增语义

### 2.1 目录与 `getdents64`

- `open` 目录（带不带 `O_DIRECTORY`）返回 `DirFile`：打开时快照，
  关闭即释放；`read/write` → `EISDIR`。
- `getdents64`（61）：
  - `d_off = index + 1`，`d_type` 来自 `lstat`/合成节点；
  - 部分 buffer 只写能放下的完整条目，未写出的不消费；
  - 首条放不下 → `EINVAL`，游标不动；
  - EOF → 0；`lseek(fd, 0, SEEK_SET)` 复位；其他 seek → `EINVAL`；
  - `dup` 共享 `DirFile`，因此共享游标。
- 子挂载点由 Core 注入父目录列表（`/` 下有 `proc`、`dev`，`/dev` 下有
  `__properties__`），并按子路径重新解析 mount 计算 `d_ino`。
- `d_ino == fstatat(d_ino)` 对宿主节点（`st_dev/st_ino`）与合成节点
  （`hash64(mount_id, guest_path)`）都成立。

### 2.2 `pwrite64` 与描述符语义

- `File::writeAt`：`HostFile` 走宿主 `pwrite`，不移动描述符 offset；
  非 seekable 描述 → `ESPIPE`；只读描述 → `EBADF`。
- stdio 0/1/2 成为描述符表里的永久条目（`closeable=false`）：
  `close(0/1/2)` 返回 0 但不丢弃；`dup(1)` 共享宿主 stdout；
  `F_GETFL` 返回真实访问模式与 `O_APPEND`。
- 可写 open 的错误不再折叠成 `EACCES`：`ENOENT/EISDIR/EROFS/EEXIST`
  各自可区分；`O_CREAT` 命中 lower 时复制到 upper 并遮蔽。

### 2.3 覆盖层与 dirfd

- 只在 lower 的删除/重命名/写意图 open → `EROFS`。
- 删除 upper 且 lower 同名 → 内存白障，后续 lookup/readdir 不再回落。
- 跨挂载 rename → `EXDEV`；同挂载 rename 保持 `st_ino`。
- `openat/fstatat/faccessat/unlinkat/renameat/mkdirat/readlinkat` 接受目录 fd；
  `AT_FDCWD` = `/`，非目录 fd → `ENOTDIR`，未打开 → `EBADF`，`..` 在根夹断。
- `/proc/self/fd/N` 对目录 fd 返回其 guest 路径。
- 补 `renameat2(276, flags=0)`：ROM bionic 的 `rename(3)` 实际走它。

## 4. 与设计的偏差

见设计文档 §9（实施偏差）。要点：

1. `File` 继续承担 `OpenFile` 角色，不重命名 vtable；新增 `open_file.hpp`
   与 `vnode.hpp` 承担 flags/身份语义。
2. 子挂载点由 VFS 注入父目录，而不是让每个后端知道自己被谁挂载。
3. D3 的覆盖层删除/重命名语义在 S1 就落地（优先级已收进 OverlayFs）。
4. 新增 `renameat2(flags=0)`，超出原设计范围但是真实目标缺口。
5. 保留 `O_CREAT` 自动建父目录（既有行为）。

## 5. `DUCKEMU_IO_TRACE` 新增行

`getdents` 沿用既有五列格式（stderr，逐次调用一行）：

```
io getdents fd=7 path=/data req=4096 -> 96
```

`path` 是目录的 guest 路径，`req` 是 guest 传入的 buffer 字节数，`->` 是
返回字节数或负 errno。`openat/read/pread/write/close/lseek` 行格式不变。
